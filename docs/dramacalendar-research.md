# DramaCalendar 졸업작품과 졸업논문

**논문명:** 웹 기반 통합 드라마 일정 관리 시스템 DramaCalendar  
**공동 작성:** 김윤열 · 문경구 · 임채환  
**프로젝트:** 동서대학교 컴퓨터공학과 졸업작품  
**문경구 담당:** 3인 팀의 팀원 / 프론트엔드

이 글은 제공된 졸업논문·심사용 결과보고서·발표 PPT를 바탕으로 정리한 포트폴리오용 요약입니다.

## 왜 이 결과물을 만들었는가

드라마의 편성 일정·출연진·장르·이미지는 방송사, OTT, 포털, 위키 등에 흩어져 있습니다. 사용자는 오늘의 방영작이나 관심 배우의 작품을 찾기 위해 여러 출처를 개별적으로 확인해야 합니다. 출처마다 작품 제목·장르·이미지 형식도 달라 통합된 화면에 그대로 사용하기 어렵습니다.

팀은 드라마 정보를 수집·정규화하고, 날짜와 관심 작품을 기준으로 탐색하는 웹서비스를 졸업작품으로 개발했습니다. 이 문제 정의와 해결 과정, 시스템 구조, 구현과 검증 내용을 졸업논문으로 공동 작성했습니다.

## 시스템과 개인 기여

팀 전체 시스템은 Python 수집 계층, PostgreSQL 정규화·ETL 계층, Node.js/Express API, React·TypeScript UI로 구성됩니다. DB·ETL·백엔드 API와 크롤링은 각 팀원의 작업이며, 문경구는 프론트엔드 페이지 구조·모달·슬라이더·페이지네이션·이미지 처리를 담당했습니다.

프론트엔드는 Home·장르·배우·캘린더 페이지로 탐색 목적을 나눴습니다. 배우와 드라마 상세는 모달로 연결해 목록을 유지하면서 연속 탐색하도록 했습니다. 모달의 배경 스크롤 잠금, Escape 닫기, 이벤트 해제 처리를 구현했고, 이미지 로딩 실패 시 placeholder로 카드 구조를 유지했습니다.

캘린더는 API의 `air_date`를 날짜별 `Map`으로 모아 화면에서 조회하도록 구성했습니다. 첨부된 코드 캡처에는 로컬 연·월·일을 조합하는 `toDateKey`와 날짜별 목록을 구성하는 `buildDailyBucket`이 있습니다. Mock 구조와 실제 API 필드의 차이를 맞추는 작업도 README와 보고서에 기록되어 있습니다.

## 논문에 정리한 내용

| 논문 구성 | 연결한 개발 내용 |
| --- | --- |
| 서론·관련 연구 | 드라마 정보 분산과 수동 탐색의 불편, 통합 정보 제공의 필요성 |
| 시스템 설계 | 수집·정규화·DB·API·UI의 계층과 데이터 흐름 |
| 구현 | 외부 출처 수집, 데이터 정제, API, React 모달과 캘린더 매핑 |
| 실험 및 결과 | 편성 조회·모달 이동·이미지 예외 처리·데이터 연동 등 기능 확인 |
| 결론 | 구현의 의미와 추천·편성 갱신 등 후속 연구 방향 |

자료는 기능 검증과 자체 평가를 중심으로 기술합니다. 별도의 사용자 대조 실험, 탐색 시간·오류율·API 지연의 정량 측정값은 제시하지 않아 포트폴리오에서도 개선율이나 성능 수치를 새로 주장하지 않았습니다. 논문을 학술지 게재·학회 발표 실적으로 표시하지 않았습니다.

## 결과와 회고

졸업작품 개발에 이어 개발 배경과 기술 선택을 글로 설명하고, 코드와 기능 확인 기록을 연구 근거로 연결하는 경험을 했습니다. 이후에는 탐색 과제를 정의해 완료 시간과 오류율을 측정하고, 날짜 경계·시간대·불완전 응답과 키보드 포커스에 대한 반복 검증을 보완할 계획입니다.

개인화 추천, 실시간 편성 갱신, 모바일 앱 확장은 후속 연구 방향으로 구분합니다.
